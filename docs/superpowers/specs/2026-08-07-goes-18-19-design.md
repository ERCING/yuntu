# GOES-18/19 Support Design

## Goal

Add GOES-18 and GOES-19 Full Disk IR, WV, and VIS imagery to the existing application without changing the existing Himawari product semantics or color schemes.

## User Scope

- Add a satellite selector with Himawari-9, GOES-18, and GOES-19.
- GOES supports Full Disk only.
- GOES supports IR B13/B14, WV B08/B09/AVG, and VIS B03.
- GOES time selection only permits UTC minutes 00, 10, 20, 30, 40, and 50.
- A missing selected time produces a clear, copyable error. The application must not silently use a nearby image.
- The displayed title, status, and output filename show the actual scan start time parsed from the selected file.

## Data Source

Use the anonymous NOAA public S3 ABI Level 2 Cloud and Moisture Imagery Full Disk product:

- GOES-18 bucket: `noaa-goes18`
- GOES-19 bucket: `noaa-goes19`
- Product prefix: `ABI-L2-CMIPF/YYYY/DDD/HH/`

Use L2 `CMI`, not L1b radiance. Infrared ABI channels C07-C16 provide brightness temperature in Kelvin; visible channels C01-C06 provide reflectance factor.

## Product Mapping

| Logical product | GOES ABI input | Render conversion |
|---|---|---|
| IR B13 | C13, 10.3 um | K to C |
| IR B14 | C14, 11.2 um | K to C |
| WV B08 | C08, 6.2 um | K to C |
| WV B09 | C09, 6.9 um | K to C |
| WV AVG | C08 and C09 | Per-pixel median, then K to C |
| VIS B03 | C02, 0.64 um | Factor to percent |

The UI retains the current logical bands. Titles additionally show the actual ABI channel or channels.

## Architecture

Introduce a provider layer that returns a normalized scene payload. The renderer consumes the payload and does not know S3 path rules, satellite-specific channel names, or fixed satellite navigation constants.

A normalized scene contains:

- Render-ready two-dimensional data, or the two inputs required to compose WV AVG.
- X and Y scan angles in radians.
- Projection metadata from the source data file.
- Actual scan start and end times.
- Satellite name, logical band, source channels, data unit, and Full Disk extent.

The GOES provider reads `CMI`, `x`, `y`, and `goes_imager_projection` from each NetCDF file. Cartopy CRS construction uses the file's projection origin, perspective point height, sweep axis, and ellipsoid metadata. No GOES navigation constant is hard-coded.

The existing Himawari implementation is migrated behind the same provider interface. The GUI continues to call one stable drawing API.

## GUI Rules

- Satellite selection appears before data type.
- Selecting GOES restricts region to Full Disk and minutes to ten-minute slots.
- Selecting Himawari restores its current region and hourly selection behavior.
- Product, band, and color-scheme controls keep their current semantics.
- Existing task-ID protection, progress display, and copyable error dialog apply to both providers.

## Performance and Integrity

- Reuse the existing three-attempt, expected-length download validation.
- Use source metadata for navigation and release NetCDF resources immediately after arrays are copied.
- Apply the existing VIS longest-edge rendering limit of 11000 pixels to ABI C02.
- Do not cache incomplete downloads.
- Do not claim that every 32 GB system can render every 11000-pixel output; pressure testing is part of acceptance.

## Acceptance

Automated tests must cover:

- GOES-18/19 bucket and year/day/hour prefix construction.
- CMIPF filename parsing and exact requested ten-minute scan matching.
- Logical-band-to-ABI-channel mapping and WV AVG calculation.
- Unit conversion for thermal and visible channels.
- CRS construction using source metadata rather than a fixed longitude.
- GUI satellite switching, minute restrictions, region restriction, and default product controls.
- Missing-file, truncated-download, and expired-task behavior.

Manual acceptance requires one IR, WV, and VIS Full Disk image for each of GOES-18 and GOES-19, with correct coastlines, source-channel title, actual scan time, saved PNG, and observed memory behavior.

## Non-Goals

- L1b radiance or self-calibration.
- RGB products, animation, lightning, radar, or overlays.
- CONUS, Mesoscale, Target, and arbitrary-minute matching.
- GK2A and Meteosat support.
